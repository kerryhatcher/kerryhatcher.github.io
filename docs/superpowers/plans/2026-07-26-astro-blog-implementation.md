# Astro Blog Rebuild Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild kerryhatcher.github.io as a static Astro 5 + Tailwind CSS 4 site with a blog, projects, about, and contact pages, deployed to GitHub Pages via Actions.

**Architecture:** A single Astro project at the repo root. Two content collections (`blog`, `projects`) authored as Markdown, rendered through shared layouts. No backend — every feature (contact, search, RSS) works from static output alone.

**Tech Stack:** Astro 5 (static output), Tailwind CSS 4 (Vite plugin) + `@tailwindcss/typography`, `@astrojs/rss`, Pagefind (static search), npm, GitHub Actions (`withastro/action` + `actions/deploy-pages`).

## Global Constraints

- Package manager: **npm** — always use `npm`, never `yarn`/`pnpm`, for every install/script command in this plan.
- `astro.config.mjs` must set `site: 'https://kerryhatcher.github.io'`. No `base` — the repo name matches the `<username>.github.io` pattern.
- Deploy workflow triggers on push to **`master`** (this repo's actual default branch), not `main`.
- No backend/server assumed anywhere — GitHub Pages serves static files only. `/contact` uses `mailto:` + links, nothing else.
- Visual system comes from `DESIGN.md` at the repo root (already committed) — do not invent new colors/fonts. Light theme: `--color-bg: oklch(0.975 0.008 252)`, `--color-ink: oklch(0.22 0.04 252)`, `--color-muted: oklch(0.45 0.03 252)`, `--color-line: oklch(0.88 0.015 252)`, font `"Noto Sans", -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", sans-serif`. Dark theme (new, derived from the same hue family): `--color-bg: oklch(0.19 0.02 252)`, `--color-ink: oklch(0.93 0.015 252)`, `--color-muted: oklch(0.68 0.02 252)`, `--color-line: oklch(0.32 0.02 252)`. No accent color — links are distinguished by underline on hover, not color.
- This is a static content site with no unit test framework. Every task's "test" step is: run `npm run build` (and/or `npm run dev`) and verify concrete, checkable output (a string present in generated HTML, a file existing in `dist/`, an HTTP 200 from the dev server) — not `pytest`. Do not skip these steps; they are this project's equivalent of a red/green test cycle.
- Every placeholder content instance (bio copy, project entries, contact details, the starter post) must get a tracked GitHub issue — see Task 13. Don't silently treat placeholder content as final.
- Routes to build: `/`, `/about/`, `/projects/`, `/contact/`, `/blog/`, `/blog/[slug]/`, `/blog/tags/[tag]/`, `/rss.xml`, `/search/`, `404.html`.

import { getCollection } from 'astro:content';
import BaseLayout from '../../../layouts/BaseLayout.astro';
import PostCard from '../../../components/PostCard.astro';

export async function getStaticPaths() {
  const posts = await getCollection('blog', ({ data }) => !data.draft);
  const tags = [...new Set(posts.flatMap((post) => post.data.tags))];
  return tags.map((tag) => {
    const filtered = posts
      .filter((post) => post.data.tags.includes(tag))
      .sort((a, b) => b.data.pubDate.valueOf() - a.data.pubDate.valueOf());
    return { params: { tag }, props: { tag, posts: filtered } };
  });
}

const { tag, posts } = Astro.props;
---
<BaseLayout title={`Tag: ${tag}`}>
  <h1 class="text-3xl font-bold py-10">Tag: {tag}</h1>
  <section class="pb-16">
    {posts.map((post) => (

        title={post.data.title}
        description={post.data.description}
        pubDate={post.data.pubDate}

  push:
    branches: [master]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest

      - name: Checkout your repository using git

    runs-on: ubuntu-latest
    environment:
      name: github-pages
